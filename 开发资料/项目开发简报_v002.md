# 桐人与亚丝娜决斗动画开发简报

版本：v002。当前依据为本版；v001 保留为历史版本。

日期：2026年10月10日

本项目制作一部约3至5分钟的《刀剑神域》同人动画，面向原作粉丝，以热血战斗为主要观看感受。目标是学习AI动画生成技术，并测试高质量双人剑斗是否可行。剧情由用户控制，本版整理用户要求与开发安排，不扩写正式剧本。

## 项目条件

- 输出与后续项目资料目录：G:\AI\ComfyUI_windows_portable_nvidia\MovieScript。该路径依据用户本次指示，取代此前 G:\GPT\SAO 的交付目录约定。
- 原作漫画目录：G:\AI\ComfyUI_windows_portable_nvidia\MovieScript\原作漫画。
- 制作方式：以用户现用的 MiniMax H3 视频参考工作流生成动画，后续继续验证和优化性能。工作流路径：G:\AI\ComfyUI_windows_portable_nvidia\ComfyUI_windows_portable\ComfyUI\user\default\workflows\MinimaxH3-战斗-视频直接参考.json。
- 语音：使用 GPT-SoVITS 训练并生成语音。语种、语料与对白表演方式待定。
- 分镜：先形成精确到秒级的剧本，再使用生图模型制作分镜。
- 人手与工具：用户一人，以及 Pro 版本 ChatGPT。
- 时间：无严格期限，可投入数月；具体预算、硬件与单次生成成本待实际需要时补充。
- 用途：fanart，学习与技术验证。具体发布平台待定。
- 配乐与剪辑：用户自行处理。
- 世界观暂不展开系统考据；发生的故事内时间很短，人物设定不变动。具体剧情和改编取舍以用户决定为准。

## 故事范围

桐人和亚丝娜在攻略战中产生分歧，决定以PVP确定谁说了算，双方进行激烈战斗。当前确认的叙事重点是决斗及其前后衔接；完整攻略战、其他支线与长篇背景尚未纳入制作范围。

## 必须保留的段落

### A 桐人从未认真到正视对手

桐人起初没有认真战斗。在拼剑过程中，亚丝娜出拳腹击，将桐人击退。随后使用桐人的第一人称视角，让观众感受到亚丝娜强大的攻击压制。桐人才意识到亚丝娜是认真的，她的骄傲不允许她松懈。

保留顺序：未认真战斗、拼剑、腹击、击退、桐人主观视角中的攻击压制、认知转变。不可只留下腹击动作而删去其后的主观体验和认知转变。

### B 亚丝娜感受到桐人开始全力应战

亚丝娜从一开始就很认真，并压制桐人。桐人下定决心使出全力时，恰与亚丝娜对视。使用亚丝娜的第一人称视角，让观众感受到桐人的锐意，随后双方战斗进入白热化。

保留顺序：亚丝娜认真压制、桐人决定全力、双方对视、亚丝娜主观视角感受锐意、激烈对抗。桐人认真应战后的双方攻防如何分配，留待动作设计讨论。

### C 烟雾突进与喜剧收尾

战斗尾声，桐人使用剑技制造强烈的爆炸烟雾，从烟雾中突刺，冲向没有防备的亚丝娜。烟雾散去，所有人看到桐人搂着亚丝娜的腰，剑架在她脖子上。

用户已确认最后一击没有打出伤害，决斗便因超时结束；桐人按剩余血量获胜。随后出现“性骚扰告警窗口”。亚丝娜对桐人邪魅一笑，桐人立刻松手，连忙摆手。亚丝娜小女生一般扭过头，说：“输给你了”。

保留上述结尾及动作顺序。最后一击不造成伤害、决斗超时、桐人按血量获胜已确定；此前血量优势如何形成，以及突刺转为搂腰架剑、烟雾形成原因和超时的画面时点，留待动作与时间设计明确。

## 分工与修改规则

用户决定剧情、原作取舍、角色解释和最终成片选择，并负责配乐与剪辑。助手整理叙事结构、提出导演表达与动作方案、维护参考和版本，并在工具可用范围内协助准备生成材料。

用户本次要求作为当前依据。助手的时长建议、动作方案和技术路线必须标为建议，未确认内容不得写成已定设定。

建议后续按项目条件、段落结构、动作因果、秒级剧本初版、生图分镜、语音与动态分镜校时、生成镜头的顺序逐步细化。评审通过时记录具体通过范围。上游条件改变时先列出受影响的段落、镜头和资产，再修改相应版本。

每个战斗段落需明确当前目标、攻防变化、位置变化及人物反应，避免只是重复高速互砍。重复招式若保留，应承担试探、识破或反制等不同作用；具体战术待用户确认。

每个场景与镜头后续使用稳定编号。保留版本编号，不覆盖旧稿；弃用版本明确标记。

## 技术验证建议

现用工作流已明确。建议从用户指定内容中抽取短片段做技术验证，并用测试结果修正后续镜头拆分；整片的生图分镜仍须以前置秒级剧本为依据。首批建议测试：

1. 双人拼剑转腹击及受击反馈，检查武器接触、持剑手、肢体关系与击退方向。
2. 桐人主观视角的连续压制，检查攻击方向是否清楚、主观身体与镜头运动是否可信。
3. 亚丝娜主观视角中的对视，检查角色身份、视线、表情及锐意变化是否可读。
4. 烟雾突进与搂腰架剑，检查遮挡前后的位置、手臂与剑的位置及最终姿态能否稳定衔接。

这些内容可以拆分测试，不预设模型能在一次生成中完成整段。测试应记录输入、参考图、参数、结果、尝试次数、耗时和问题类型。成功样本同时需要检查能否复现。

高质量判断建议包含：身份与服装稳定、剑和手关系正确、攻防因果可读、空间连续、打击反馈可信、人物表演明确，以及生成过程可重复。仅速度快或特效强，不足以证明战斗质量。

当前工作流参数见下文，属于保存时的测试配置；最终成片规格和单段生成长度仍可优化。界面文字是否后期叠加、对白与音效如何分工，留待后续落实。

## 秒级剧本与分镜衔接建议

用户要求先有精确到秒级的剧本，再使用生图模型制作分镜。建议将秒级剧本作为正式制作材料，采用统一时间轴记录镜头，而非仅给出场景总时长。

每个镜头建议记录：镜头编号、全片起止时间、计划时长、镜头内动作时点、景别与视角、角色位置和朝向、持剑手与剑的位置、攻防因果、对白与内心旁白、声音提示，以及分镜图所需的起始和结束状态。

计划时长与生成时长分别记录：前者用于成片节奏，后者可含模型对齐与剪辑余量。模型实际出手时机仍需通过生成与剪辑验证，文字时间戳不等于模型可以逐帧准确执行。

先根据对白文本与表演意图估算时长，形成秒级剧本初版；该版本确定后再制作生图分镜。GPT-SoVITS得到可用语音后，用实际语速、停顿与动态分镜复核时间；若需要调整，先更新对应时间轴，再同步受影响的分镜和视频任务。语音训练可提前准备，不要求等全部剧本定稿后才启动。

分镜图侧重构图、表演和起止姿态；动态分镜检验真实播放节奏；视频参考或其他经验证的控制方式负责补充运动依据。具体提示词应从已确认镜头材料派生，避免改写提示词时另起剧情。

## 下一步需要明确的创作条件

1. 开场攻略分歧是否沿用漫画中牺牲NPC换取攻略效率的争论，还是用户另定原因。
2. 最终画风与角色造型依据。现有工作流提示词和角色图只反映当前测试，不自动成为本片定稿。
3. 对白与语音采用日语、中文或其他语言；是否使用内心旁白表达两个主观视角中的认知变化。
4. 战斗场地与旁观者范围。建议先明确空间类型及是否需要克莱因等具名角色，以便控制场景和资产数量。

这些问题影响对白、构图和秒级节奏；模型性能优化可继续独立进行。无需当前就确定每一招的名称或全部生成参数。
